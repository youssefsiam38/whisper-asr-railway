# Security

## Reporting

Open an issue at https://github.com/youssefsiam38/whisper-asr-railway/issues for a problem with the
wrapper. Report anything in the application itself to
https://github.com/ahmetoner/whisper-asr-webservice. Do not include credentials, tokens or public
hostnames in an issue.

## The central fact

Whisper ASR Webservice has no authentication. `app/webservice.py` defines `/`, `/asr` and
`/detect-language`, and not one of them checks a credential. There is no setting that turns
authentication on, because the project is built to run on a private network behind something else.

Deployed unmodified to a platform that assigns a public hostname, the result is an open speech-to-text
service. Anyone who finds the URL can submit audio, consume the CPU you are paying for, and, if you
ever point it at a paid model backend, spend against it. This template exists to close that.

## What is exposed

| Route | Anonymous | Authenticated |
|---|---|---|
| `/healthz` | 200 `ok`, or 502 while the model loads | same |
| `/` and `/docs` | 401 | the interactive API documentation |
| `/openapi.json` | 401 | the API schema |
| `/asr` | 401 | transcription |
| `/detect-language` | 401 | language detection |

`/healthz` returns a single word. It proxies the app's `/openapi.json` to decide what to say and
then discards that response, so the schema itself is not published.

## Deliberately opting out

`WHISPER_ALLOW_PUBLIC=true` removes authentication completely. The container then logs a warning on
every start. Set it only when the instance is on a private network or behind another gateway that
authenticates for you. On a public Railway domain it means an open endpoint.

## Secrets

- `WHISPER_AUTH_PASSWORD` is generated by the template with `${{secret(24)}}` and is never printed
  by the wrapper. The start-up log reports the username and the password's length, nothing more.
- The password is hashed with `caddy hash-password` before it reaches disk. The generated Caddy
  configuration holds only the bcrypt hash, is written `0600`, and lives outside the volume so it is
  regenerated on every start rather than persisted.
- `HF_TOKEN`, if you use the WhisperX engine, is passed straight to the application and is not
  logged.
- Nothing is baked into the image at build time. There are no credentials in the Dockerfile, in a
  build argument, or in any layer.

## Client credentials

Basic authentication is used because it is what a scripted client can send in one flag. Every
consumer of this API, `curl`, a subtitle tool, a language model pipeline, sends the same header. If
you need per-client credentials, add users to the `basic_auth` block by forking this repository; the
wrapper generates the block from one username and one password on purpose, so the template has
nothing for a deployer to fill in.

Rotate the password by changing `WHISPER_AUTH_PASSWORD` in the service variables and redeploying.
There is no session state to invalidate.

## Transport

Railway terminates TLS at its edge and the certificate covers the generated domain. Plain HTTP
redirects to HTTPS. Caddy runs with `auto_https off` because it is behind that edge and never needs
to obtain a certificate itself.

## Data handling

This service stores no transcripts and no audio. A request carries audio in, the response carries
text out, and neither is written to the volume. The only durable state is the downloaded model.

Audio is processed in memory and in the container's temporary space by `ffmpeg` for the duration of
the request. A crash mid-request leaves nothing behind, because the container's filesystem is
replaced on restart and the volume holds only model weights.

## Third-party calls made by the application

On a cold start the application downloads model weights: from OpenAI's CDN for the bundled
`openai_whisper` engine, and from Hugging Face for `faster_whisper` and `whisperx`. After that it
makes no outbound calls. Nothing is sent anywhere at transcription time; the model runs locally.

## Updates

The upstream image is pinned by digest. A version bump is a pull request that changes the digest, is
tested by CI against the real image, and is released as a new wrapper tag. See `MAINTENANCE.md`.
